# DOCUMENTO MAESTRO · PORTFOLIO PERSONAL
## Franco Núñez · V1 · 29/09/2026

> **Fuente de verdad estratégica y creativa del proyecto.**  
> Este documento define qué estamos construyendo, qué debe transmitir y qué principios no deben degradarse durante el trabajo con Atlas, Claude Design y Claude Code.  
> **No es el copy final, no es un wireframe rígido y no prescribe cada animación.** Es el sistema rector.

---

# 1. NORTE DEL PROYECTO

Construir un portfolio personal **hiperprofesional, internacional y memorable**, con un estándar de dirección de arte, interacción y ejecución comparable al de portfolios de creative developers, product designers y estudios digitales de primer nivel.

El sitio debe demostrar una combinación poco común:

**Design × Engineering × Product × Business**

No buscamos “una web linda para mostrar trabajos”.  
Buscamos crear una **experiencia digital que sea, por sí misma, una demostración de capacidad**.

La reacción deseada del visitante es:

> “Si su propio portfolio está construido a este nivel, quiero ver lo que puede construir para nosotros.”

---

# 2. OBJETIVO COMERCIAL

El portfolio debe elevar radicalmente la percepción profesional de Franco y funcionar como activo comercial para:

- clientes de mayor ticket;
- startups y empresas tecnológicas;
- proyectos digitales ambiciosos;
- oportunidades internacionales;
- colaboraciones con estudios/agencias;
- productos SaaS, ecommerce y experiencias digitales premium.

El portfolio debe posicionar a Franco **por encima de la categoría de “freelancer que hace páginas web”**.

No competir por precio.  
Competir por **criterio, producto, diseño, ejecución y nivel percibido**.

---

# 3. POSICIONAMIENTO

Franco no se presenta exclusivamente como:

- Web Developer
- UI Designer
- Frontend Developer
- “Full Stack Developer”

Esas capacidades existen, pero son componentes de una propuesta más amplia.

## Posicionamiento conceptual

**Digital Product Designer & Developer**  
que diseña y construye productos, sistemas y experiencias digitales de extremo a extremo.

La identidad debe comunicar:

**Strategy → Design → Engineering → Launch**

El portfolio debe demostrar que puede entender un problema de negocio, convertirlo en producto, diseñarlo y llevarlo hasta producción.

---

# 4. PRINCIPIOS DE EXPERIENCIA

## 4.1 Impactar → Demostrar → Convertir

Toda la experiencia responde a tres etapas:

### IMPACTAR
Crear una impresión inmediata de calidad, criterio y capacidad.

### DEMOSTRAR
Probar ese nivel mediante productos reales, interfaces, casos, interacción y ejecución.

### CONVERTIR
Hacer extremadamente fácil iniciar una conversación o proyecto.

El impacto visual sin evidencia es decoración.  
La evidencia sin dirección artística es un portfolio convencional.  
Necesitamos ambas.

---

## 4.2 El portfolio ES una pieza del portfolio

La propia experiencia debe demostrar:

- dirección de arte;
- motion design;
- interacción;
- 3D/WebGL cuando aporte;
- frontend avanzado;
- storytelling;
- sensibilidad tipográfica;
- performance;
- atención al detalle.

No debemos depender únicamente de screenshots de proyectos anteriores para demostrar capacidad.

---

## 4.3 Experiencia antes que plantilla

Evitar deliberadamente la estructura visual típica:

**Hero → About → Skills → Projects → Contact**

La información puede existir, pero debe convertirse en una narrativa espacial, editorial y cinematográfica.

---

# 5. ESTÁNDAR VISUAL

La referencia mental es:

**creative developer / digital studio / product designer internacional**

No:

**portfolio freelance genérico.**

La experiencia debe sentirse:

- premium;
- precisa;
- experimental;
- tecnológica;
- editorial;
- cinematográfica;
- contemporánea;
- deliberada.

Debe existir una identidad reconocible incluso si se eliminan nombre y logo.

## Evitar

- templates reconocibles;
- estética SaaS genérica;
- glassmorphism gratuito;
- gradientes sin intención;
- cards por todas partes;
- iconografía genérica;
- barras de porcentaje de skills;
- timelines convencionales;
- exceso de badges;
- animaciones únicamente decorativas;
- “dark mode + neon = futurista”;
- copiar visualmente un sitio de referencia.

---

# 6. DIRECCIÓN DE ARTE

Antes de construir el prototipo definitivo deben explorarse **3 direcciones creativas claramente diferentes**.

Cada dirección debe definir:

1. concepto rector;
2. composición;
3. tipografía;
4. paleta;
5. tratamiento de imágenes/interfaces;
6. lenguaje 3D;
7. lenguaje de motion;
8. comportamiento del Hero;
9. tratamiento de proyectos;
10. personalidad general.

Elegiremos una dirección o una combinación deliberada antes de profundizar el prototipo.

El objetivo no es encontrar “la más bonita”.

El objetivo es encontrar una identidad que sea:

**memorable + sofisticada + técnicamente demostrable + coherente con Franco.**

---

# 7. MOTION & 3D

Motion no es decoración añadida al final.

Es parte de la arquitectura de la experiencia.

## Motion debe servir para

- dirigir atención;
- revelar información;
- conectar escenas;
- comunicar jerarquía;
- crear profundidad;
- explicar productos;
- producir momentos memorables.

## Recursos posibles

- scroll-driven storytelling;
- transformaciones 3D;
- parallax con profundidad real;
- objetos WebGL;
- shaders;
- kinetic typography;
- masking;
- clipping;
- morphing;
- pinned scenes;
- smooth transitions;
- cursor interactions;
- layered interfaces;
- controlled camera movement.

No necesitamos utilizarlos todos.

**Sofisticación > cantidad de efectos.**

Cada movimiento debe tener intención.

# 8. ARQUITECTURA NARRATIVA V1

La estructura inicial del portfolio será:

## 00 — PRELOADER / ENTRY
Una entrada breve y distintiva.  
Nunca una espera artificialmente larga.

## 01 — HERO / SIGNATURE EXPERIENCE
Primer momento memorable.

Nombre / identidad + posicionamiento + pieza visual o sistema interactivo protagonista.

El visitante debe percibir nivel antes de analizar racionalmente el contenido.

## 02 — MANIFESTO
Declaración breve de filosofía y capacidad.

Tipografía y motion como protagonistas.

Debe establecer la intersección:

**Design × Engineering × Product**

## 03 — SELECTED WORK
El corazón probatorio del portfolio.

Entre **3 y 5 proyectos seleccionados**, tratados como piezas principales y no como una galería de cards.

## 04 — PROJECT IMMERSIONS
Cada proyecto importante puede convertirse en una pequeña experiencia:

- interfaces en profundidad;
- scroll sequences;
- cambios de escala;
- escenas de producto;
- detalles;
- contexto mínimo;
- resultado y alcance.

Mostrar producto > describir producto.

## 05 — CAPABILITIES
Organizar capacidades por resultados, no por herramientas.

### Digital Products
SaaS, dashboards, plataformas y sistemas operativos.

### Commerce Experiences
Ecommerce, ordering systems y experiencias orientadas a conversión.

### AI & Automation
Agentes, workflows, automatización e interfaces inteligentes.

### Interactive Web
Motion, 3D e interfaces inmersivas.

## 06 — PROCESS / THE BUILD
Mostrar capacidad end-to-end:

**Understand → Strategize → Design → Prototype → Engineer → Launch**

Debe sentirse como una construcción, no como un diagrama corporativo.

## 07 — LAB / EXPERIMENTS
Espacio para demostrar capacidades que los proyectos comerciales todavía no muestran.

Posibles experimentos:

- WebGL;
- shaders;
- interacción;
- motion studies;
- interfaces conceptuales;
- AI experiences;
- exploraciones 3D.

El Lab permite que el nivel creativo del portfolio no quede limitado por el brief de clientes anteriores.

## 08 — ABOUT
Presentación personal breve y segura.

Sin autobiografía extensa.

Conceptualmente:

**Based in Uruguay. Building globally.**

Mostrar persona, criterio y forma de trabajar.

## 09 — TECHNOLOGY / CREDIBILITY
La tecnología respalda el trabajo; no protagoniza el posicionamiento.

Puede incluir, entre otras:

Next.js · React · TypeScript · Supabase · PostgreSQL · Vercel · AI tooling

Debe integrarse al sistema visual, nunca presentarse como barras de “nivel”.

## 10 — FINAL EXPERIENCE / CONTACT
Cierre memorable y extremadamente simple.

CTA principal orientado a iniciar proyecto/conversación.

El final puede recuperar o transformar elementos del Hero para generar cierre narrativo.

---

# 9. SELECTED WORK — CRITERIO

No llenar el portfolio por cantidad.

**3 proyectos extraordinariamente presentados son mejores que 12 proyectos mediocres.**

Cada proyecto seleccionado debe aportar al menos una de estas señales:

- complejidad de producto;
- nivel visual;
- profundidad técnica;
- impacto comercial;
- capacidad end-to-end;
- sistema real funcionando;
- especialización relevante.

Los proyectos se elegirán estratégicamente.

Candidatos iniciales pueden incluir productos SaaS, ecommerce, sistemas gastronómicos y experiencias visuales, pero la selección definitiva se hará por **valor para el posicionamiento**, no por cronología.

---

# 10. CASE STUDIES

No convertir los casos en documentos interminables.

Cada caso debe responder rápidamente:

**What was it?**  
**What was the challenge?**  
**What did I create?**  
**How does it work?**  
**What was my role?**

La interfaz y el producto deben ocupar más espacio que el texto.

Cuando existan resultados verificables podrán incorporarse.

Nunca inventar métricas, clientes, testimonios o impacto.

---

# 11. COPY

El copy debe ser:

- breve;
- seguro;
- preciso;
- internacional;
- humano;
- sin humo;
- sin clichés de agencia.

Evitar frases como:

> “Transformamos ideas en experiencias digitales únicas.”

La diferenciación debe demostrarse principalmente mediante **trabajo y ejecución**, no mediante adjetivos.

El idioma principal se decidirá antes de producción final teniendo en cuenta el posicionamiento internacional.

---

# 12. MOBILE

Mobile no será una versión reducida del desktop.

Debe diseñarse como experiencia propia.

Las escenas 3D, pinned sections y animaciones deberán adaptarse deliberadamente a:

- pantalla;
- rendimiento;
- interacción táctil;
- longitud del scroll;
- legibilidad.

Nunca sacrificar usabilidad por mantener un efecto de desktop.

---

# 13. PERFORMANCE & CRAFT

Un portfolio técnicamente impresionante que funciona mal contradice su propio mensaje.

La implementación final debe cuidar:

- Core Web Vitals;
- carga progresiva;
- peso de assets;
- GPU usage;
- WebGL lifecycle;
- responsive behavior;
- reduced motion;
- accesibilidad;
- navegación por teclado;
- estabilidad visual;
- fallbacks.

La complejidad técnica debe sentirse invisible para el visitante.

---

# 14. STACK

La implementación se definirá según las necesidades del diseño.

Base probable:

- Next.js
- React
- TypeScript
- Tailwind
- Framer Motion / Motion
- GSAP cuando esté justificado
- Three.js / React Three Fiber cuando esté justificado
- shaders/WebGL cuando aporten al concepto
- Vercel

**La herramienta se elige después del efecto deseado.**

No diseñar alrededor de una librería.

# 17. CRITERIO DE ÉXITO

El portfolio habrá cumplido su función cuando consiga simultáneamente:

### PERCEPCIÓN
Franco parece capaz de ejecutar trabajo digital de alto nivel internacional.

### DIFERENCIACIÓN
El sitio no podría confundirse fácilmente con otro portfolio.

### EVIDENCIA
Los proyectos demuestran que detrás de la estética existe producto real.

### CRAFT
Interacción, motion, responsive y performance reflejan dominio técnico.

### CLARIDAD
En pocos minutos queda claro qué hace Franco y qué tipo de proyectos puede construir.

### CONVERSIÓN
Un cliente, founder, estudio o empresa interesado sabe inmediatamente cómo iniciar una conversación.
