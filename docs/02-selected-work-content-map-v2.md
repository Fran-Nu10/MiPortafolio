# 1. OBJETIVO DE SELECTED WORK

`Selected Work` no debe funcionar como una galería de sitios web ni como una grilla de tarjetas.

Debe demostrar que Franco puede trabajar en distintas capas de un producto digital:

**PRODUCT → SYSTEMS → INTERACTION → ART DIRECTION → COMMERCE**

Los proyectos seleccionados deben sentirse diferentes entre sí y, juntos, construir una percepción única:

> Franco diseña y construye productos digitales completos, combinando criterio de producto, diseño, ingeniería y ejecución visual.

La interfaz real debe ser protagonista. El sistema ENSAMBLE funciona como marco narrativo para revelar el trabajo, no para competir con él.

# 2. FEATURED BUILDS

## BUILD 01 — TravelSuite360

### Rol dentro del portfolio
**PRODUCT SYSTEM / SaaS**

Es la pieza que debe comunicar mayor profundidad de producto y arquitectura.

No debe presentarse como “una web para una agencia”, sino como un sistema digital de operación para agencias de viaje.

### Qué debe demostrar
- Diseño de producto complejo.
- Arquitectura de información.
- Sistemas con múltiples módulos.
- CRM y operación.
- Inbox/conversaciones.
- Cotizaciones, viajes y reservas.
- Usuarios, permisos y contexto multi-agencia.
- Integración entre interfaz, datos y automatización.
- Capacidad de construir software que se utiliza para operar un negocio.

### Lectura deseada
> “Puede diseñar y construir un producto SaaS real, no solamente interfaces atractivas.”

### Tratamiento ENSAMBLE recomendado
**Sheet Type A — Elevation**

TravelSuite360 es el mejor candidato para mostrar una interfaz desktop dominante y permitir que módulos secundarios aparezcan como piezas relacionadas del mismo sistema.

La transición desde construcción isométrica hacia interfaz frontal debe ser especialmente fuerte aquí:

`DATA → API → COMPONENTS → INTERFACE → PRODUCT`

### Material visual prioritario
Dashboard, TravelChat/inbox, CRM, cotizaciones, viajes/reservas y cualquier pantalla que evidencie profundidad operacional.

No intentar mostrar todos los módulos simultáneamente. Elegir las interfaces que mejor prueben que existe un sistema detrás.

### Claim estructural
**A complete operating system for travel agencies.**

El copy definitivo puede cambiar, pero debe conservar esta idea.

## BUILD 02 — Prospector

### Rol dentro del portfolio
**CREATIVE ENGINEERING / INTERACTIVE COMMERCE**

Debe demostrar la capacidad de convertir una experiencia comercial en una pieza digital altamente visual e interactiva.

### Qué debe demostrar
- Dirección visual aplicada a producto.
- Motion avanzado.
- Scroll-driven storytelling.
- Interacciones.
- Diseño responsive.
- Ecommerce/menu digital.
- Capacidad de crear demos comerciales personalizables.
- Creative development sin sacrificar utilidad.

### Elementos visuales relevantes
El hero de hamburguesa construido por capas, sus estados armada/explotada y la transición hacia el menú son material especialmente valioso.

El menú tipo tracklist y la relación entre lista, producto activo e imagen permiten demostrar que la interacción continúa después del hero.

### Lectura deseada
> “Puede construir experiencias web que son producto y demostración técnica al mismo tiempo.”

### Tratamiento ENSAMBLE recomendado
No reducir Prospector a una captura estática.

El portfolio debe aprovechar la lógica de capas del propio proyecto y hacerla dialogar con ENSAMBLE.

Puede comenzar como objeto/producto construido por partes y terminar frontalmente en la interfaz real.

### Claim estructural
**A restaurant commerce demo engineered to sell the experience before the pitch.**

No convertir este claim en una afirmación de resultados comerciales si no existen datos verificables.

## BUILD 03 — Santi Nuca

### Rol dentro del portfolio
**ART DIRECTION / EDITORIAL EXPERIENCE**

Este proyecto introduce una dimensión que los demás no cubren: dirección artística, fotografía, composición editorial y una experiencia donde el contenido visual domina la interfaz.

### Evidencia visual disponible
Las capturas muestran:

- Layout editorial de gran formato.
- División vertical de pantalla.
- Uso extremo de espacio negativo.
- Fotografía en blanco y negro y color.
- Numeración de trabajos `01–06`.
- Navegación mínima.
- Tipografía de escala extrema.
- Composiciones asimétricas.
- Vistas editoriales `FORMA / LÍNEA / TEXTURA`.
- Secuencias donde fotografía y tipografía comparten el viewport.
- Identidad `SANTI NUCA` como elemento compositivo.
- Índice/trabajos como sistema de navegación.

### Qué debe demostrar
- Dirección de arte.
- Composición.
- Jerarquía tipográfica.
- Tratamiento fotográfico.
- Ritmo editorial.
- Diseño de portfolio para una disciplina creativa.
- Capacidad de dejar que el contenido sea protagonista sin caer en una plantilla de galería.

### Lectura deseada
> “No solamente sabe construir sistemas: tiene criterio visual y puede dirigir una experiencia editorial.”

### Tratamiento ENSAMBLE recomendado
Este proyecto debe ser deliberadamente diferente a TravelSuite360.

Cuando el objeto ENSAMBLE rote hacia frontal, la interfaz debe ocupar el espacio con muy poca instrumentación externa.

Las fotografías deben respirar.

Evitar llenar este proyecto de cotas o callouts técnicos. Según la propia regla ENSAMBLE, medir solamente aquello que realmente comunica una decisión de diseño.

### Secuencia visual sugerida
`SANTI NUCA opening → numbered work → editorial triptych → photographic composition`

La interfaz puede presentarse casi como páginas de una publicación que se ensamblan y se desplazan.

### Claim estructural
**An editorial portfolio built around image, rhythm and restraint.**

## BUILD 04 — Chef Arturo

### Rol dentro del portfolio
**PREMIUM COMMERCE / ART DIRECTION × TRANSACTION**

Chef Arturo debe demostrar que una experiencia comercial puede tener una identidad visual fuerte sin perder claridad transaccional.

No presentarlo solamente como “ecommerce de pastelería”.

### Evidencia visual disponible

Las capturas proporcionadas muestran:

- Identidad `CHEF Arturo by Julia Montserrat`.
- Fondo crema y lenguaje editorial.
- Paleta verde oscuro + naranja/acento.
- Hero con muchísimo espacio negativo.
- Copy:
  `Pastelería, merienda y lunch para fiestas`.
- CTA `Ver catálogo`.
- CTA `Pedir por WhatsApp`.
- Imagen de producto dentro de marco arqueado.
- Expansión de la fotografía durante la experiencia.
- Fotografía gastronómica a gran escala/full viewport.
- Sección editorial:
  `El detalle también forma parte del pedido`.
- Sección `Fechas que importan`.
- Tres modalidades visibles:
  `Compra del día`
  `Encargo con fecha`
  `Lunch para eventos`
- Catálogo completo.
- PDP de producto.
- Selector de cantidad.
- Stock del día.
- Mercado Pago.
- `Agregar al carrito`.
- `Consultar por WhatsApp`.
- Información de retiro y entrega.

### Qué debe demostrar
- Dirección visual aplicada a ecommerce.
- Diseño de marca digital.
- Storytelling visual.
- Catálogo y navegación.
- Arquitectura de distintos modos de compra.
- PDP transaccional.
- Carrito.
- Integración del flujo comercial con WhatsApp y Mercado Pago.
- Capacidad de unir experiencia premium y función comercial.

### Lectura deseada
> “Puede convertir una marca gastronómica en una experiencia de compra digital con identidad propia.”

### Hero Moment

La transformación visual del hero debe ser el momento protagonista del proyecto dentro del portfolio:

`COPY + SMALL IMAGE → IMAGE EXPANSION → CINEMATIC PRODUCT PHOTOGRAPHY`

No conviene representarlo únicamente mediante una captura desktop dentro de un frame.

La imagen debe poder crecer, atravesar el marco ENSAMBLE y convertirse temporalmente en el espacio visual dominante.

### Secuencia narrativa recomendada

**01 — BRAND / HERO**

Presentar el enorme espacio negativo, headline y pequeña imagen arqueada.

**02 — EXPANSION**

La fotografía crece y el sistema editorial empieza a ocupar el viewport.

**03 — COMMERCE MODES**

Mostrar `Fechas que importan` y sus tres rutas comerciales.

Esto prueba que detrás de la estética existe arquitectura de compra.

**04 — PRODUCT**

Entrar a una PDP real.

Mostrar imagen, nombre, precio, cantidad, stock, CTA principal y WhatsApp.

**05 — TRANSACTION**

Cerrar mostrando que la experiencia termina en una acción comercial real: carrito / compra / consulta.

### Tratamiento ENSAMBLE recomendado
Chef Arturo debe funcionar como una combinación de **Sequence + Detail**.

No necesita la densidad sistémica de TravelSuite360.

El sistema ENSAMBLE debe retirarse progresivamente cuando la fotografía crece y reaparecer cuando se inspecciona la capa transaccional.

Esto crea un contraste útil:

`ART DIRECTION → COMMERCE ARCHITECTURE → TRANSACTION`

### Material visual prioritario

1. Hero con espacio negativo e imagen arqueada.
2. Estado de expansión de imagen.
3. Fotografía gastronómica full viewport.
4. `Fechas que importan`.
5. PDP de Cookie Levain.
6. Elementos de carrito/compra cuando sea necesario.

No es necesario utilizar todas las capturas.

### Claim estructural
**Editorial commerce designed to turn a food brand into a complete buying experience.**

No atribuir conversiones, ventas o resultados económicos sin evidencia.

# 5. RELACIÓN CON ENSAMBLE 2.0

ENSAMBLE continúa siendo el sistema rector.

Cada proyecto debe entrar y salir del mismo mundo físico, pero la interfaz real debe conservar su identidad.

### Regla central

**ENSAMBLE presenta el trabajo. No lo uniformiza.**

Cuando el proyecto está en estado isométrico, vemos cómo está construido.

Cuando rota a frontal, vemos el producto tal como es.

La transición debe reforzar:

> Construction explains. Product proves.

Las capas reutilizadas entre proyectos solo deben marcarse como compartidas cuando realmente exista una relación defendible. No inventar “reuse” para justificar la animación.

---

# 6. CAPTURAS DESKTOP Y MOBILE

Las capturas desktop proporcionadas son material válido para el portfolio y pueden utilizarse en desktop y en composiciones responsive.

No es necesario volver a fotografiar cada pantalla desde un teléfono para que el portfolio funcione bien en mobile.

Sin embargo:

- una captura desktop no debe simplemente reducirse hasta volverse ilegible;
- en mobile pueden utilizarse crops, pan, ventanas parciales y secuencias;
- para demostrar una interfaz mobile real, utilizar capturas mobile reales cuando existan;
- Claude Code debe adaptar la composición al viewport, no tratar la captura como un póster fijo;
- la información importante debe permanecer legible;
- los Hero Moments pueden reinterpretarse para touch y scroll vertical.

**Mobile tiene dirección propia. No es desktop encogido.**

2. No inventar métricas.
3. No inventar testimonios.
4. No inventar clientes.

8. Priorizar interfaces reales sobre mockups decorativos.
9. Evitar explicar cada tecnología.
10. Mostrar complejidad mediante la experiencia, no mediante párrafos técnicos.
